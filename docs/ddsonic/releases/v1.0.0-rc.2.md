## What changed since v1.0.0-rc.1

No feature was added, and no provider, schema or dependency changed. Everything since the first candidate is identity and packaging:

- **Renamed from ddmus to ddsonic.** The executable, the config, data, cache and download folders, `DDSONIC_CONFIG_DIR`, the `[ddsonic]` config section, the socket and log, the MPRIS bus name, the client name and User-Agent, the release files, the SBOM, the notices, `ddsonic-bin` and the repository.
- **No compatibility code.** ddsonic does not read ddmus's folders or a `[ddmus]` section. State is moved by hand, once: [files.md](../files.md#moving-from-ddmus-100-rc1-and-earlier). `~/Music/ddmus` stays where it is, because saved tracks are remembered by full path.
- **One definition of the name.** `appdir.Name`; `TestProductNameIsWrittenInOnePlace` lists the five production files that still spell it in a string.
- **The header** reads `🦆 ddsonic <version>`, the version dimmed. **The MPRIS Identity** is `ddsonic`.
- **The sign-in pages** a browser shows after a Spotify or YouTube Music sign-in are titled ddsonic (they said cliamp).
- **Removed, inherited from cliamp:** its website and `install.sh`, the Nix flake, the desktop entry, the icons and the Windows resource file. None reached a user through the release archive.

## Found by the review of this candidate, and fixed before the tag

Codex's release-readiness review of the first candidate commit (`2358319`) raised two findings in the migration documentation; both were fixed, and the gates were run again on the commit that followed.

1. **A dead link to the migration instructions (MEDIUM).** The changelog's rename entry and the README linked to `docs/ddsonic/files.md` by a path inside the repository. The binary archive ships both files without `docs/`, and the release notes are the changelog's section, so in both places the link to the one page an rc.1 user needs led nowhere. The two links, and the changelog's other link to the same page, now give its full address.
2. **The `sed` line missed header spellings the loader reads (LOW).** ddmus read `[DDMUS]` and an indented `[ddmus]` as the section; the documented `sed` rewrote only the exact lower-case, unindented header, leaving such a config's settings ignored. It now rewrites the header however it is capitalised or indented.
