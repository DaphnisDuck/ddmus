## What changed since v1.0.0-rc.2

No feature was added, and no provider, catalog, sync or player code, schema or dependency changed. Everything since the second candidate is identity, branding, documentation and packaging:

- **A logo and an icon:** the owner's approved artwork, kept whole and unedited in `assets/branding` (raster; about 16 MB with its masters and sources). `TestBrandingMatchesItsManifest` holds it to its manifest.
- **A launcher entry:** `ddsonic.desktop` (`Terminal=true`, `Icon=ddsonic`) and the icon in eight sizes, in the release archive's `share/`, in `ddsonic-bin`, and installed by `make install`.
- **MPRIS `DesktopEntry`** is `ddsonic`, so a desktop's media controls can find the icon.
- **`ddsonic --help`** opens with "music for your terminal", and `--provider` calls `cliamp` the legacy provider key for Internet Radio. The key is unchanged.
- **The terminal's title** reads `ddsonic` from the start; cliamp's intro line no longer scrolls through it.
- **cliamp's empty-pane hints** for Local and YouTube Music name ddsonic's folder and `ddsonic setup`.
- **The README** shows the logo and a screenshot, says how the name and artwork may be used, and says that a plain `go build` names the binary `cliamp` (the Go module path is kept on purpose). The archive and the AUR package carry the two images beside their copy of the README.
- **The source archive** grows from 39 MB to 57 MB with the artwork and the screenshot (owner's decision: the masters and sources stay). The binary archive grows from 15.8 MB to 18.6 MB with the icons and the README's two images.

## Found by the audit of this candidate, and fixed before the tag

Codex's audit of the first candidate commit (`f333b25`) raised three findings. The owner chose to fix all three before the tag. The review of those fixes raised a fourth, in the fix for the third.

1. **No release record for the candidate (MEDIUM).** Gate C asks for one per candidate, and the two earlier candidates carried theirs in the tagged tree. This record is the fix, and the commit that holds it is the candidate.
2. **The launcher entry's `Exec` path was escaped once, not twice (LOW).** For a source install, `packaging/desktop.sh` writes the executable's full path as one quoted argument. The desktop entry format then wants every backslash of a string value doubled; without that, a path holding `$`, a quote or a backtick gave an entry that launchers reject. The script now encodes both layers. The README's command for a release install wrote the path unquoted, so a space in it broke the entry; it now quotes it. `TestDesktopInstall` decodes the line as a launcher does, where it used to assert the insufficient text.
3. **The packaged README showed two broken images (LOW).** The archive and `ddsonic-bin` shipped `README.md` without the logo and the screenshot it shows. Both now carry the two files at the paths the README names them by: `packaging/release.sh` copies every image the README shows, and stops the build if one is missing; the recipe installs them beside the README; the release workflow checks them in the fresh container; `TestReadmeImagesShipWithIt` holds the README to images the build can ship.
4. **The release workflow's new check did not parse (found in review of fix 3; it would have stopped the release).** The check for the images was added inside the single-quoted script the workflow hands to the fresh container, with a comment that held an apostrophe. The apostrophe closed the script, so the step would have failed on the tag, before the attestation and the draft. The dry run had passed without running the script as the workflow file finally held it. The comment is reworded; `TestWorkflowScriptsParse` reads every `run` script of the workflows with `bash -n` and fails on the old text; the dry run now takes the step's script from the workflow file.

Found in the field test of `v1.0.0-rc.2`, and settled before this candidate:

- **A plain `go build` names the binary `cliamp`.** Go takes the name from the module path, which ddsonic keeps for cheap upstream merges. No supported build or install path is affected. Documented, and `TestMakeNamesTheBinary` holds the Makefile to `ddsonic` (owner, 2026-10-05).
- **A header reading "DaphnisDuck's Music Player".** A stale local build from before the rename's header change, not this code; no configuration or saved state can change the header.

## Findings carried over

The five findings recorded for `v1.0.0-rc.1` under "Findings, not fixed in this candidate" (the yt-dlp prompt, "sync failed" before anything is set up, lyrics when LRCLIB is busy, a second instance and the MPRIS name, a token refresh that fails at once) are unchanged in this candidate. None blocks it.

Accepted and deferred, for consideration after v1.0.0 (owner, 2026-10-05): **a carriage return in the install path gives an invalid launcher entry (LOW).** `packaging/desktop.sh` encodes backslashes, quotes, backticks, `$` and `%` in the `Exec` path, but writes a carriage return (or another control character) as it is, and `desktop-file-validate` rejects the entry. Found by the review of the fixes (run `rc3-fixes-2`); it predates them, and no code is changed for it in this candidate.

Kept on purpose, not findings: the `cliamp` provider key and the "cliamp radio" label under Radio → Browse Stations (it is the radio service the cliamp project runs); the hidden Logo visualizer, which no name, index or key can select; the Go module path.
