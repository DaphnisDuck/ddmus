## Found by the audit of this candidate, and fixed before the tag

Codex's audit of the first candidate commit (`f333b25`) raised three findings. The owner chose to fix all three before the tag.

1. **No release record for the candidate (MEDIUM).** Gate C asks for one per candidate, and the two earlier candidates carried theirs in the tagged tree. This record is the fix, and the commit that holds it is the candidate.
2. **The launcher entry's `Exec` path was escaped once, not twice (LOW).** For a source install, `packaging/desktop.sh` writes the executable's full path as one quoted argument. The desktop entry format then wants every backslash of a string value doubled; without that, a path holding `$`, a quote or a backtick gave an entry that launchers reject. The script now encodes both layers. The README's command for a release install wrote the path unquoted, so a space in it broke the entry; it now quotes it. `TestDesktopInstall` decodes the line as a launcher does, where it used to assert the insufficient text.
3. **The packaged README showed two broken images (LOW).** The archive and `ddsonic-bin` shipped `README.md` without the logo and the screenshot it shows. Both now carry the two files at the paths the README names them by: `packaging/release.sh` copies every image the README shows, and stops the build if one is missing; the recipe installs them beside the README; the release workflow checks them in the fresh container; `TestReadmeImagesShipWithIt` holds the README to images the build can ship.

Found in the field test of `v1.0.0-rc.2`, and settled before this candidate:

- **A plain `go build` names the binary `cliamp`.** Go takes the name from the module path, which ddsonic keeps for cheap upstream merges. No supported build or install path is affected. Documented, and `TestMakeNamesTheBinary` holds the Makefile to `ddsonic` (owner, 2026-10-05).
- **A header reading "DaphnisDuck's Music Player".** A stale local build from before the rename's header change, not this code; no configuration or saved state can change the header.

## Decisions

- **The name and the artwork** are outside the code's licenses. The README's License section carries the owner's wording: the branding assets may be redistributed with ddsonic and its packages or distributions, technical transformations included, and may not identify a modified or unrelated project. `assets/branding/source/build.py` is MIT code. `LICENSE` and `LICENSE-GPL-3.0` are unchanged.
- **The screenshot** is the owner's capture, approved as it is, with the album's cover art and the local path it shows.
- **Left out of this candidate:** a social preview image, the repository's topics and homepage, a favicon, AppStream metadata, and the website.
